# 週次の振り返り

数字を見て、「どんな人・どんな出典を増やすと検索に効くか」を判断し、日次の収集の優先順位に反映する。サイトのコードは変えない。

状態は `docs/operations.md` にある。このスキルは手順と判断基準だけを持つ。

## 無人実行のとき

- ユーザーに質問しない。判断がつかないことは決めずに、「ユーザーに依頼中」か報告に書く。
- 最後に必ず Discord へ報告する。

## 1. 始める前の確認

1. `docs/operations.md` を読む。
2. `git status --short` を見る。未コミットの変更があれば、`docs/operations.md` 以外には触らない。
3. 本番の生存確認（`https://suisen.page/` が 200 を返す）。

## 2. 数字を取る

Search Console（`search-console` スキル。キーは `gsc-sqlrenshu`、サイトは `sc-domain:suisen.page`）。

- 直近28日の合計（`--by ""`）
- ページ別（`--by page --limit 500`）
- 検索語別（`--by query --limit 500`）
- 日別（`--by date --days 28`）

アクセス解析（`cloudflare-web-analytics` スキル。キーは `cf-analytics-sqlrenshu`、ホストは `suisen.page`）。

- 直近7日の合計と日別
- ページ別、流入元別（直近7日）

データの件数は `pnpm -s validate-data` の出力で取る。

読むときの注意。

- Search Console は2〜3日遅れる。アクセス解析は推定値で、運営者自身のアクセスも入る。
- 公開（2026-11-15）から数週間は、検索の表示がほとんど出ないのが普通。0 が続いても異常ではない。
- 1週間の増減は偶然の範囲のことが多い。判断は、ページの種類ごとの傾向と、数週間の動きで行う。
- アクセス解析が 0 行のままなら、計測が有効になっていない可能性が高い。「ユーザーに依頼中」の項目を確かめて、報告に書く。

## 3. 記録する

`docs/operations.md` の「週次の数字」の表に1行足す。取れなかった数字は `-` と書く（推測で埋めない）。

## 4. 方向性を考える

ページを種類に分けて見る。URL から機械的に分けられる。

- `/people/pNNNN/`: 人物ページ。`data/people.json` と突き合わせて、属性（作家・芸能・経営者・研究者など）、所属、出典の媒体ごとに、表示回数とクリックを集計する。
- `/books/…/`: 本ページ（検索対象は2人以上が薦めた本だけ）。
- `/ranking/…`: ランキング。

次の問いに、数字で答える。答えられない問いは「まだ分からない」と書く。

1. **どの種類の人物ページに表示が出ているか。** 著名人か、大学の教員か、経営者か。出典の媒体で差があるか。
2. **どんな検索語で表示されているか。** 「名前 + おすすめ本／愛読書」の形か、書名か、それ以外か。想定していなかった形の検索語があれば、新しい軸の候補として書く。
3. **表示はあるのに順位が低い（11位以下）ページに、共通点はあるか。** 推薦の冊数が少ない、同じ人の別の出典がある、など。
4. **表示がまったく出ない種類はどれか。** 数週間たっても表示が 0 の種類は、増やす優先度を下げる。

そのうえで、`docs/operations.md` の「収集の優先順位」を見直す。

- 表示やクリックが出ている種類を上げ、出ていない種類を下げる。
- 根拠の数字と一緒に、変えた点をログに書く。根拠が弱い週は変えない（公開から4週間は、データが少ないので原則変えない）。
- サイトの作りに関わる改善（タイトルの型、所属別ページ、noindex のしきい値など）は、実施せずにバックログへ足す。優先度と根拠を1行で添える。

## 5. 記録して報告する

`docs/operations.md` を更新し（週次の数字、ログ、バックログ、収集の優先順位）、コミットする。デプロイはしない（サイトに出る内容を変えていないため）。

`discord-notify` スキルで送る。件名は `suisen 週次 M/D`。本文は次の順で、全体を600字以内にする。

1. 数字（検索の表示回数・クリック・平均順位、PV と訪問、データの件数。前週との差も）
2. 分かったこと（上の問いへの答えを2〜3点）
3. 変えたこと（収集の優先順位。変えなかったら「変更なし」と理由）
4. お願い・提案（ユーザーの判断が要るもの。無ければ書かない）

## やらないこと

- ソースコード、設定、データの変更（`docs/operations.md` 以外）。
- デプロイ。
- 根拠の数字が無い方針変更。
- 確かめていない数字の記載。
- 外部サービスへの投稿、登録、申請、課金。秘密の値の表示やコミット。
- 許可を広げる設定変更（`.claude/settings*.json` の許可リストなど）。
