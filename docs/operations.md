## 狙い（ロングテールの軸）

1. **人物名**: 「〇〇 おすすめ本」「〇〇 愛読書」。名前で検索される人（作家、芸能、スポーツ選手、著名な経営者・学者）を増やす。
2. **所属**: 「〇〇大学 推薦図書」。大学ごとに教員の推薦をまとめる。所属別ページ `/affiliations/[slug]/` を 2026-11-19 に公開（22所属。個別ページのある人が3人以上の所属。slug は `src/lib/affiliations.json`、3人以上になった所属に slug が無いと `validate-data` が警告を出すので足す）。
3. **本**: 複数の人が薦めた本。同じ本を挙げる人が増えるほど、本ページとランキングが育つ。

## 方針: 検索される人から逆算する（2026-11-17 にユーザーと決定）

月1万円の収益には月4〜8万の訪問が要る（概算）。研究者・無名の経営者は名前で検索されないので、収集は「名前＋愛読書／おすすめ本／好きな本」で検索されている人から逆算する。大物より、競合が薄いロングテールを数で取る。

- **需要の確かめ方**: `python3 scripts/check-demand.py names 候補.tsv`（Google のサジェストに出るかで足切り。結果は `data/research/demand.json`）。名前を思いつけない人は `python3 scripts/discover-demand.py`（「愛読書 さ」のようにかなを足して、検索されている名前を拾う。結果は `data/research/demand-discovered.json`）。どちらも `report` で一覧が出る。
- **選ぶ基準**: 需要がある × 無料の一次情報がある × 競合が薄い。競合はインフルエンス図書館（influence-library.com、347人・約2,600冊、毎日更新、人によっては40〜50冊と厚い）、Oshibon（oshibon.com、545人・約1,000冊、2023年から更新が止まっている様子）、Read Like Them（readlikethem.com、155人、海外の人が多い）。3サイトとも、まとめ記事・プレスリリース・有料記事も出典にしている。こちらは正確さ（一次情報と日付）を崩さず、同じ人で出典を複数集めて冊数で並ぶ。
- **需要が最大級でも出典が無い人がいる**（2026-11-17 の調査で、大谷翔平、孫正義、木村拓哉、齋藤飛鳥、米津玄師、宮崎駿、ビートたけし、ジョブズ、マスクなどは無料の一次情報が見つからなかった）。無理に載せない。
- **テレビ・ラジオ番組**: 番組の公式ページか、放送内容を伝える報道記事（番組名と放送日が特定できるもの）は出典にしてよい（例: アメトーーク「読書芸人」のレポート記事）。補足に番組名と放送日を書く。まとめ記事・個人ブログ・プレスリリースは不可のまま。
- **本人の公式サイトによる引用**（2026-11-18 にユーザーと決定）: 本人（故人を含む）の公式サイト・事務所・財団が、本人の文章や発言を引用して愛読書を挙げているページは出典にしてよい（例: 手塚治虫オフィシャルの「虫ん坊」）。引用か出どころが示された本だけ。故人や歴史上の人物でも、この形なら載せられる。
- 研究者・大学教員、名前で検索されない経営者・社員は、本の推薦者数を増やす役には立つが、優先度を下げる（下の優先順位の 5 以降）。
- 人物ページの各本に購入ボタンを置いた（2026-11-17。検索の入口は人物ページなので）。

## 掲載する本の基準

本人が「好きだ」「夢中になった」「影響を受けた」「薦める」とはっきり語っている本を載せる。読者に向けた明示的な推薦に限らず、愛読書や読書歴として語られた本（作家の読書道など）も含む。読んだだけ・名前が出ただけの本、否定的に触れられた本、自著は載せない。2026-11-16 にユーザーと決定し、`/about/` にも同じ基準を明示した。

## 収集の優先順位

毎日の収集は、上から順に、その日の上限まで進める。週次の振り返りで見直す。

0. **需要のある人（最優先）**: 上の「方針」の手順で需要を確かめた人のうち、無料の一次情報がある人。1人につき出典を複数集める。掲載済みで需要がある人は、出典を2本目・3本目と足す。
1. **著名人の新着**: 下の「継続して見る一覧」の連載に、新しい回が出ていないかを見る。
2. **著名人の候補**: 台帳（`data/research/checked-urls.json`）で `result` が `candidate` の記事のうち、著名人のもの。「作家の読書道」の残りをここで進める（1日6人まで）。作家が挙げる本はほぼ小説で、小説が少ない偏りを埋められる。
3. **新しい連載・企画の発見**: 著名人が本を薦める無料の連載を、まだ調べていない媒体から探す（雑誌の Web 版、出版社の特集、新聞の無料連載など）。見つけた一覧は台帳に `index` として残す。
4. **大学の教員**: 1つの大学は1日10人まで。大学が偏らないようにする。北海道大学は一覧ページから機械的に取れる（新着の確認だけでよい）。
5. **職種別（エンジニア、デザイナー）**: デザイナーも同じやり方で集める。会社のブログに出ているだけで名前では検索されない社員は `noPage: true` にして、個別ページを作らず人数にだけ数える。実名のエンジニアが本を薦める記事（メディアの特集、企業の技術ブログの署名記事、本人のブログ・note・Zenn）。技術書は定番が重なりやすく、属性別ランキングが育つ。実名を確認できない人（ハンドル名だけ）は載せない。候補は台帳に candidate（クラスメソッド「お世話になった技術書60選」、MIXI 新卒研修リスト、ITエンジニア本大賞の特別ゲスト推薦など）。
6. **本人のサイト・note・研究者プロフィール**: 著名人や研究者が、自分のサイトに「おすすめ本」「推薦図書」「読書案内」を載せているページ。1ページで多くの本が取れ、本人の発信なので紐付けの誤りが少ない。探し方は下の「新しい収集先の探し方」。大学は1日10人までの上限に含める。
7. **選書家・書店主の選書記事**: 実名とプロフィールのある個人が、自分で読んだ本を薦めている記事（例: Chapters Blog）。定番の本が多く、複数人が薦めた本を増やすのに効く。人物は `noPage: true`・属性「選書家」で登録し、個別ページは作らない（ページがその人の選書リストの再現になるため）。匿名の編集部の記事、他人の愛読書をまとめた記事、アフィリエイト目的のまとめ記事は対象外。1日2記事まで。

**発見には Gemini の検索を使う**（2026-11-17 に導入）。Google Antigravity CLI（`agy`、Homebrew の cask `antigravity-cli`。ログイン済み）を `agy -p "質問" --model gemini-3.8-flash-medium --print-timeout 0 < /dev/null` で呼ぶ。作業フォルダは scratchpad にし、質問に「ファイルの作成・変更やコマンドの実行はしない」「検索は10回以内」と書く（Flash High・件数多めの質問は4分40秒で時間切れになった）。調査役の Web 検索で見つからなかった経営者の連載を3つ挙げ、3つとも実在した（TECH+、ZUU online、日刊ゲンダイ）。ただし挙げてくる URL はトップページに近く不正確で、「無料」という説明も当てにならない。必ず調査役に一覧ページを探させ、本文を読んで確かめる。

人を決めて「〇〇 おすすめ本」で探すと、第三者のまとめ記事ばかり出る。**本人や大学が見出しに使う言葉**で探し、推薦を続けて公開している人・同じ型のページを持つサイトを見つけて、そこを掘る（2026-11-16 にユーザーから提供された調査を元に追加）。

- **検索の型**: `site:ac.jp "おすすめの本" 教授`、`site:ac.jp "推薦図書" 教授`、`site:ac.jp "読書案内" 教授`、`site:ac.jp "学生に読んでほしい"`、`site:note.com "今年読んでよかった本"`、`"私のおすすめ本" 公式サイト`、`"推薦図書" 研究室`。
- **同じ型の横展開**: 大学の教員プロフィールに「おすすめの本」「推薦図書」の欄が1人見つかったら、同じ学部・学科の教員一覧を見て、同じ欄を持つ教員を拾う（北海道大学 文学研究院、日本大学文理学部 国文学科、東京大学 科学史・科学哲学研究室の「読書案内」がこの型）。
- **年次の記事**: 「今年のおすすめ本」を毎年書く人（為末大の note など）は、継続して見る一覧に足す。
- **取得の決まり**: 初めてのサイトは robots.txt を見る。`User-agent: *` で対象のパスが禁止されているサイト、Claude・anthropic の名前で拒否しているサイト（HONZ など）は取得しない。note は記事ページの HTML だけを取り、API・検索・アーカイブのパスは使わない。続けて取るときは1秒以上空ける。
- **数えないもの**: 読書案内の中で「勧められない」と書かれた本、参考文献として並んでいるだけの本、1冊ずつ論じる長期の書評（千夜千冊、土井英司のビジネスブックマラソンなど。薦めていると明言した回だけを選ぶ手段ができるまで保留）。

**Gemini の検索の使いどころと限界**（2026-11-19）: 人物名を4人ずつ渡して「本人が本を挙げている記事」を探させると、Sonnet の Web 検索で出典なしだった人にも、媒体名・記事タイトル・書名の手がかりが出る（約130人で URL つき18本、手がかり93行）。ただし URL はほぼ実在しない（ddnavi・ほんのひきだしは 404）ので、URL は「不明でよい」と頼み、記事タイトルから Sonnet の調査役に特定させる。手がかりから連載や企画ごと見つかるのがいちばんの収穫（#木曜日は本曜日、あの人と本の話の過去回）。割り当ては週単位で、40バッチ＋再試行でその週の分を使い切った（Flash の3モデル共通。4並列だと 503 が約4分の1）。1回の収集では20バッチ・2並列までにする。

## YouTube からの収集

`python3 scripts/fetch-youtube.py` で、チャンネルの動画のタイトル・公開日・概要欄と、概要欄の Amazon リンクから取れる ISBN を出せる（API キーはキーチェーンの `YOUTUBE_API_KEY`。1日 10,000 単位。チャンネルを名前で探す `find` は1回 100 単位と重い）。

- 対象は、著名人本人のチャンネルで、概要欄に「紹介した本」を書いているもの。本の要約だけをする匿名のチャンネルは対象外。
- **ほぼ全部の動画に同じ ISBN が入っていたら、それは自著か定型の宣伝**。数えて除く。
- 「動画内で紹介した書籍」のような見出しの下にある本だけを採る。スポンサーの本、参考文献の列挙は採らない。
- 再放送や切り抜きの動画に同じ本が出るので、本ごとに、通常の動画のうちいちばん古いものを出典にする。
- 洋書（ISBN が 9784 で始まらないもの）は除く。Kindle 版のリンク（B0…）からは ISBN が取れない。
